C++ 條件式語義

December 16, 2025 · 8 min read
yhchen
software developer

在 C++ 裡，條件式語義是一組「如果你提供了這些成員，語言就會賦予你某種語義」的結構。以我個人的觀點來看，跟之後的 Concept 與 Contract 是同一種概念，因此後面我會簡稱其為「合約」

從迭代器開始​

在 std::iterator 的範例中，展示了簡單的疊代器實現。關注到代碼本身：

template<long FROM, long TO>
class Range
{
public:
    // member typedefs provided through inheriting from std::iterator
    class iterator : public std::iterator<
                                std::input_iterator_tag, // iterator_category
                                long,                    // value_type
                                long,                    // difference_type
                                const long*,             // pointer
                                long                     // reference
                            > {
        long num = FROM;
    public:
        explicit iterator(long _num = 0) : num(_num) {}
        iterator& operator++() { num = TO >= FROM ? num + 1: num - 1; return *this; }
        iterator operator++(int) { iterator retval = *this; ++(*this); return retval; }
        bool operator==(iterator other) const { return num == other.num; }
        bool operator!=(iterator other) const { return !(*this == other); }
        reference operator*() const { return num; }
    };
    iterator begin() { return iterator(FROM); }
    iterator end() { return iterator(TO >= FROM? TO + 1 : TO - 1); }
};

在後面的範例代碼中，使用了 auto range = Range<15, 25>() 建立了一個迭代器，看起來「似乎」是透過使用繼承 std::iterator 的 class Iterator，使得 Range 可以進行迭代，但實際上，只是 std::iterator 幫忙滿足了迭代器所需要的介面。

迭代器的合約​

在 LegacyIterator，提到了什麼是「可用於識別和遍歷容器元素的類型」。

如果一個型別 It，滿足以下條件：

  • CopyConstructible
  • CopyAssignable
  • Destructible
  • Swappable

且具有以下公開成員：

  • value_type
  • difference_type
  • reference
  • pointer
  • iterator_category

並且假定 It r，

  • *r 是可解引用的且
  • ++r是可以遞增的，並且回傳值為 It&

...，這些就是在描述一個迭代器「最低限度」應該滿足哪些條件

到底什麼是迭代器？​

參考Iterator Library：

在 C++ 標準中，迭代器首先被定義為一種可與序列互動的位置值。所謂 input iterator，並不是因為它有某個型別別名，而是因為對它進行解參考操作時，必須能得到某種類型的值。這個值被稱為 iterator 的 value type，但重點不在型別名稱，而在於一個語義承諾：這個 iterator 所代表的位置，必須是「可讀的」。

需要滿足 *i 的操作，且 i 的型別 T 不為 void

與之相對，output iterator 的定義並不關心能否讀取。標準只要求，存在一組型別，使得對 iterator 解參考後進行賦值是合法的。也就是說，output iterator 的核心角色是「寫入目標」，而不是資料來源。這解釋了為什麼某些 output iterator 看起來幾乎無法使用 *i 讀取任何東西，卻仍然是完全合法的 iterator。

需要滿足 *i = V 的操作

當 iterator 支援相等比較時，標準進一步要求它具備一個差值型別，用來描述兩個位置之間的距離。這個差值型別不是為了數學運算，而是為了表達「位置之間的位移關係」。它再次強調了一個事實：iterator 關心的是位置，而不是元素本身。

static_cast<decltype(i)>(nullptr) - static_cast<decltype(i)>(nullptr) 是合法的

並非所有 iterator 值都可以被解參考，只有那些對 *i 有定義的值，才被稱為 dereferenceable。這表示同一個 iterator 型別，在不同狀態下，可能代表不同性質的位置。有些位置可以讀寫資料，有些位置則只能作為邊界存在。

其中最典型的邊界，就是 past-the-end iterator。對於任何 iterator 型別，標準都保證存在一個指向「序列尾端之後」的位置。這個位置是合法的 iterator 值，可以用來比較或作為結束條件，但標準明確規定它不可被解參考。這說明 iterator 的值域，刻意包含了「不指向任何元素」的狀態。

範圍的定義​

雖然迭代器的定義很清楚了，但是還是要有個「可以操作迭代器」的東西，所以還有 Range 的定義：

A range can be denoted by either

  • [i, s), with an iterator i and a sentinel s that designate the beginning and end of the computation (i and s can have different types), or
  • i + [​0​, n), with an iterator i and a count n that designate the beginning and the number of elements to which the computation is to be applied. Iterator-sentinel range An iterator and a sentinel denoting a range are comparable. [i, s) is empty if i == s; otherwise, [i, s) refers to the elements in the data structure starting with the element pointed to by i and up to but not including the element, if any, pointed > to by the first iterator j such that j == s.

A sentinel s is called reachable from an iterator i if and only if there is a finite sequence of applications of the expression ++i that makes i == s.

If s is reachable from i, [i, s) denotes a valid range.(Since C++20)

Counted range A counted range i + [​0​, n) is empty if n == 0; otherwise, i + [​0​, n) refers to the n elements in the data structure starting with the element pointed to by i and up to but not including the element, if any, pointed to by the result of n > applications of ++i.

A counted range i + [​0​, n) is valid if and only if

  • n == 0; or
  • all of the following conditions are satisfied:
    • n is positive,
    • i is dereferenceable, and
    • ++i + [​0​, --n) is valid.

範圍並不是某個特定型別，而是一種描述計算適用區間的方式。只要能說清楚從哪個位置開始，以及在什麼條件下停止，就構成一個範圍。

最常見的形式是 iterator–sentinel range，記為 [i, s)。其中 i 表示起始位置，s 表示結束條件，兩者可以是不同型別。當 i == s 時，範圍為空；否則，範圍涵蓋從 i 開始，經由有限次 ++i 推進，直到首次滿足 j == s 為止的元素。只有當 s 能在有限步內從 i 抵達時，這個範圍才是合法的。

另一種形式是 counted range，記為 i + [0, n)。它不依賴結束標記，而是以次數定義範圍。當 n == 0 時範圍為空；當 n > 0 時，起始位置必須可解參考，且每一次推進後，剩餘的計數仍然形成一個合法的範圍。

首先考慮一個迭代器的定義：

  • 要可以解參考: *i
  • 要可以計算位置差異: i* - i*

在考慮範圍的定義：

  • 要可以遞增: i++，且回傳值要符合 T&, T 不為 void
class Iterator {
public:
  using value_type = int;
  using difference_type = decltype(static_cast<int*>(nullptr) - static_cast<int*>(nullptr));
  using reference = int&;
  using pointer = int*;
  using iterator_category = std::input_iterator_tag;

    Iterator(int* ptr) : cur(ptr) {}

    int& operator*() const {
        return *cur;
    }

    Iterator& operator++() {
        ++cur;
        return *this;
    }

    friend bool operator!=(const Iterator& a, const Iterator& b) {
        return a.cur != b.cur;
    }
private:
    int* cur;
};

接著定義 Range：

class Range {
public:
  Range(int* begin, int* end) : b(begin), e(end) {}
  Iterator begin() const { return Iterator(b); }
  Iterator end()   const { return Iterator(e); }
private:
  int* b;
  int* e;
}
int main() {
int data[] = {1, 2, 3};

  for (int x : Range(data, data + 3)) {
     std::cout << x << '\n';
  }
}

這個例子滿足了一些要求：

  • Iterator 裡只有一個 int* cur，它代表目前所在的位置；end() 回傳的 iterator 則代表 past-the-end 位置。
  • 當 cur == end 時，iterator 仍然是合法的，但 *it 不該被呼叫。range-for 本身也不會在這個狀態解參考。
  • 它定義了位置的推進與停止條件：++ 前進位置，!= 用來判斷是否抵達邊界。這正是 range-for 的整個控制邏輯。

在 Iterator 的定義中，使用了 using ... 暴露出一些型別的 Alias，比方說 Iterator::value_type 為 int。但是這些其實不是迭代器必要的條件，所以即使沒有這些 Tag 也可以運作。

他們是為了滿足「標準函式庫用到的迭代器」，這個更加深層的概念而衍生的。

合約是分層的，語言需要的合約，和標準庫演算法需要的合約，不是同一組。

為什麼要提及「合約」​

在 C++ 中，許多語言能力並不是透過繼承關係或明確的介面來定義，而是透過一組隱含的規則來成立。這些規則不寫成基底類別，也不強制你實作某個介面，但只要滿足了，語言或標準庫就會賦予你特定的語義。若不先說清楚這種規則的性質，後續討論往往只剩下操作符清單，卻無法理解它們為何存在。

在早期(C++11/14)，會看到大量的 *trait 被使用，他們是專門在編譯期提供型別資訊的工具，讓程式碼能根據型別特徵做分支或選擇實作。雖然忘記在哪本書看到的，但曾有提到：

trait 是一種在編譯期提供資訊，進而決定編譯策略的手段

這也跟 SFINAE 的使用有關係。

而目前提到「合約的概念」，是因為未來我想解釋 coroutine，必須從語言的合約開始描述，所以先記錄下這篇文章。
